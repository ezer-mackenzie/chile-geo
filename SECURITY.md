# Security policy

## Supported versions

Security fixes are applied to the latest released minor version. Pre-release builds and unmaintained versions may not receive patches.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Send a private report to the maintainer through the security contact on the repository hosting page. Include the affected version, reproduction steps, impact, and any suggested mitigation. Avoid accessing data that is not yours and stop testing if it could disrupt another system.

The maintainer will acknowledge a report when possible, assess it, coordinate a fix and disclosure, and credit reporters who request attribution. No response-time guarantee is offered for this volunteer project.

## Scope

Relevant issues include package supply-chain risks, unsafe browser behavior, prototype pollution, unexpected code execution, and vulnerabilities in published build artifacts. Boundary accuracy, visual simplification, and ordinary application integration questions are not security vulnerabilities.
